# Lean 4 formalisation of the reduction behind H₃ ≤ 13

Lean 4 with Mathlib (toolchain and Mathlib `v4.35.0-rc3`). Every step between "every certificate leaf
passes the leaf check" and "every convex body in ℝ³ is covered by 13 translates of its interior" is
proved here. There are no `sorry`s. The trusted base is one axiom (the certificate) and one
`native_decide` computation, described below.

## Build

    lake exe cache get                  # prebuilt Mathlib
    lake build                          # a few minutes once Mathlib is in place; peak RAM several GB

Every file imports Mathlib, and `lake build` elaborates independent files in parallel, each with its own copy
of Mathlib in memory. On a machine with under about 32 GB, build one module at a time in dependency order
(`lake build Hadwiger.Basic`, then `Hadwiger.Symmetry`, and so on, as listed in `Hadwiger.lean`).
    lake env lean Hadwiger/Audit.lean   # prints the axioms of each headline result

## Trusted base

`lake env lean Hadwiger/Audit.lean` reports that `H3_le_13` depends on Lean's standard `propext`,
`Classical.choice` and `Quot.sound`, and on exactly two further assumptions.

1. `all_leaves_pass : ∀ k, CertIdx k → Certified (startBox k)` (`Final.lean`). This is the certificate.
   * `CertIdx` covers 39,950 start boxes of side 1/10: the 39,380 boxes meeting Prymak's `U^D_20` and
     the 570 extension boxes in `ExtraBoxes.lean`.
   * `Certified B` means that `B` is tiled by a midpoint-bisection tree and every leaf passes `LeafOK`.
   * `LeafOK` is the structure-based predicate with **strict** containment: every covered point lies in
     the interior of its translate.
   * It is checked on all 7,561,583 leaves by `code/newmethod/certcheck_strict.py`, which tests exactly
     this predicate. `code/replay/hcheck.py --strict` checks all leaves again with a separately written,
     structure-free (weaker) predicate.
   * The link between the JSON data and `LeafOK` is by reading the code. The conventions are: `cubeBit`
     in `itertools.product` order, `edgeList` in `itertools.combinations` order, faces indexed
     x0, x1, y0, y1, z0, z1, `chordDir` as `certcheck.chord_dir`.
2. `gridCheck_true._native.native_decide.ax_1_1` (`Orbit.lean`), generated by `native_decide`. It is
   the finite fact that every 1/10-box with `k₀, k₁, k₂ ≤ 4` has a cube-symmetry image among the
   certified start boxes. `code/replay/orbitboxes.py` and `code/newmethod/certcheck_ext.py` check the
   same fact. Kernel `decide` on 125,000 boxes × 48 symmetries is not feasible.

Strict containment is used because Prymak's Lemma 2.4(ii) ("some translate of `Q_P` lies in `int O_p`")
does not hold at some box corners; `code/corner_example.py` gives an exact example. With strict
containment Lemma 2.4(ii) is not needed: `int Q_P ⊆ int O_p` follows from Lemma 2.4(i).

The symmetry reduction runs in two steps. Any configuration is first moved to `p₀, p₁, p₂ ≤ 1/2`
(`exists_sym_mem_DStar`); then the grid orbit is used (`orbit_cover`). Prymak's region `D` is not a
fundamental domain (`Counterexample.lean`), which is why the 570 extension boxes are needed.

## Main theorems

    theorem H3_le_13 (K : Set E3) (hK : IsConvexBody K) : CoveredByInteriorTranslates 13 K
    theorem H3_le_13_homothets (K : Set E3) (hK : IsConvexBody K) :
        ∃ r, 0 < r ∧ r < 1 ∧ ∃ x : Fin 13 → E3, K ⊆ ⋃ i, (fun y => x i + r • y) '' K

`H3_le_13_of_symcover` and `H3_le_13_of_cover` use no axioms. Each takes an arbitrary family of
certified boxes that covers every configuration up to symmetry (respectively, covers `D*`).
